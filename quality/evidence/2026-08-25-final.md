## 已验证故障样本

- 重放同一 HMAC nonce：第二次返回 403。
- challenge 后立即轮换密钥：轮换前 nonce 在 30 秒窗口可完成一次，新 nonce 不能用旧代。
- cookie 缺 CSRF、跨源 HTTP、跨源 WebSocket：均返回拒绝。
- API 密钥改为 `0644`：Ubuntu 权限检查拒绝；密钥和目录正常为 `0600`/`0700`。
- 配置 `os.replace` 注入失败：原文件字节与版本保持不变，临时文件清除。
- `server.yaml` 端口 99999：语义校验拒绝且不替换。
- 插件导入抛异常：服务和其他插件继续可用，诊断保留异常。
- 墙钟开始时间故意设为未来：单调耗时仍约 5 秒且不为负。
- 过期终态任务与日志：按独立期限清理；排队任务及其日志保留。

## 浏览器证据与工具兼容性披露

学习目标是使用 Browser 技能检查只读态、管理员导航、任务详情、模板、Monaco、窄屏和键盘焦点。Codex 浏览器桥接两次都在连接前被管理员 Hook 拒绝，错误为：`未知写能力未提供可解析的本地目标；管理员 Hook 按 fail-closed 拒绝`。源码诊断确认该 Hook 要求所有 MCP 写能力提供本地路径，而浏览器 Node REPL 参数没有路径字段；修改 URL 无法恢复。

实际影响仅限 Codex 内置浏览器桥接，未降低项目验收范围。替代方案是项目内 `tools/run_browser_quality.py`：每轮先构建当前前端，以临时根目录和随机端口启动 LocalFlow，再驱动系统 Microsoft Edge。结果覆盖匿名管理入口缺席、空码 401、键盘管理员登录、刚完成焦点确认、详情去敏边界、xterm 输出与温和中断、verification case 扫描/筛选/选择、Monaco 离线加载和文件创建、axe WCAG A/AA serious/critical 清零、390px 无溢出且导航单行、阴性对照之后零控制台错误。

收据为 `quality/evidence/browser/browser-receipt.json`；截图为 `admin-task-detail.png`、`admin-template-cases.png`、`admin-config-monaco.png`、`admin-mobile-390.png`。恢复内置桥接仍需管理员 Hook 为该工具提供可解析的只读目标契约，但项目 QA 不再依赖它。

源码证据摘要在计算前统一 CRLF 为 LF，保证 Windows 采集的收据可在 GitHub Linux checkout 上复验；截图仍按原始二进制字节计算。

自主学习资料获取还发生过一次失败：freedesktop.org systemd 在线手册返回 `400 Timeout fetching`。影响是该单一网页不可用；已采用 systemd 官方 GitHub 手册源码与 Ubuntu 24.04/systemd 255 实测替代。恢复需要目标站点恢复响应或网络代理可访问。
