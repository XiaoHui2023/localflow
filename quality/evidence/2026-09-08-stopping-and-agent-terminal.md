# 2026-09-08 stopping and agent terminal evidence

## Natural reproductions

- Before the model change, `tests_v2/test_scheduler.py -k stop_progress_extension` failed because both progress fields were rejected as extra input.
- Before observer recovery, `tests_v2/test_scheduler.py -k transient_wait_failure` failed after one injected wait-channel exception: the live child was marked `lost` and its log pump remained pending.
- The first Docker systemd run failed with `Failed to connect to bus: No such file or directory` because the invocation used stale UID 999; read-only inspection proved the container service account is UID 997 and the bounded rerun used `/run/user/997/bus`.
- Before controller force-stage serialization, the shutdown cgroup fixture ended with stale `stop:0:signal` even though the controller had already sent SIGKILL. The shutdown path now cancels the competing soft sequence and persists `sigkill` before force cleanup.

## Accepted behavior

- `timeout_seconds` remains backward-compatible fixed grace by default.
- An opted-in output-progress action resets only its quiet window and requires a finite absolute ceiling.
- Result observation errors probe ownership and retry while live; they do not manufacture a terminal state.
- Controller shutdown owns the final force transition and waits until the executor proves the complete owner inactive.
- AI clients use signed raw UTF-8/Base64 input, named controls, resize, offset logs and full-log search; the administrator browser uses the ACK-gated WebSocket. A successful terminal write is not treated as task completion.

## Research

- systemd service documentation uses a graceful stop timeout followed by SIGKILL and supports repeated timeout-extension notifications for legitimate long stops: https://github.com/systemd/systemd/blob/main/man/systemd.service.xml
- systemd documents the required kill and timeout properties for transient units: https://github.com/systemd/systemd/blob/main/docs/TRANSIENT-SETTINGS.md
- systemd source explicitly warns that `KillMode=none` disables lifecycle management and recommends `control-group` or `mixed`: https://github.com/systemd/systemd/blob/main/src/core/load-fragment.c
