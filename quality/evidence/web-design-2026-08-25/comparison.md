# 首屏元素关注度审计

核心问题：现在有什么任务需要关注，我下一步要打开哪一个或运行哪一个？

| 元素 | 用户关心 | 缺失影响 | 频率 | 决策 |
| --- | --- | --- | --- | --- |
| `LF` 方块、LocalFlow、副标题 | 无；浏览器标题已表明产品 | 无 | 始终 | 删除 |
| 任务/运行/配置/API/设置导航 | 切换核心工作 | 无法完成工作 | 始终/按权限 | 左上角纵向 rail；管理员入口按能力出现 |
| “管理员/摘要只读”右上角 | 用户不需要持续读取身份诊断 | 无；权限由可用功能表达 | 始终 | 删除 |
| 登录码横条 | 本机管理员进入 | 无法管理 | 仅未认证 | 改为 launcher 自动交换；失败才显示短提示 |
| 主题按钮 | 使用惯用明暗外观 | 长时间使用不舒适 | 低频 | 移入设置页，偏好持久化 |
| 与导航同义的页面标题 | 页面导航已给出上下文 | 无 | 始终 | 删除；反例登记在 `docs/ui-counterexamples/` |
| 五项筛选 | 用户明确只要求 API 筛选 | 无 | 始终 | 删除 |
| 手动刷新 | 页面已每 3 秒自动同步 | 无 | 始终 | 删除 |
| 空“正在运行/等待队列”板块 | 没有任务时不支持任何决策 | 无 | 空时 | 条件隐藏 |
| 历史任务 | 回看结果和新完成 | 丢失主要观察能力 | 有数据 | 保留 |
| API 文档 | 管理员查接口 | 无法发现调用契约 | 按需 | 管理员 tab，endpoint 渐进展开 |
| 详情和终端 | 核对任务、查看输出、中断 | 丢失核心控制能力 | 按需 | Round 6 改为任务行下原位 disclosure |
| 手动“扫描”按钮 | 发现固定目录中的配置/Case | 增加一次无必要操作 | 每次运行 | 删除；路径或插件变化后自动发现 |
| “磁盘配置/磁盘版本” | 用户关心配置与冲突，不关心存储介质 | 无 | 配置操作 | 改为“任务配置/最新版本/配置已同步” |
| 设置页服务器时间 | 校准前核对当前时间 | 缺少参照且需手填 | 按需 | 从服务器加载、持续显示并预填输入 |

## 成熟方案差异矩阵

| 候选 | 优点 | 不适合处 | 本项目决定 |
| --- | --- | --- | --- |
| Fluent Nav | 一级导航清楚、图标与文字并存、选中态和键盘规则成熟 | 默认抽屉宽度与多级能力对本项目过重 | 采用窄 rail 和交互原则，自写离线 CSS |
| Atlassian Navigation/Forms | token、焦点、表单分组和组件状态一致 | 完整组件栈与复杂产品布局增加依赖 | 采用间距/边界/反馈原则，不引入包 |
| GitHub Actions 固定目录 | 配置即代码、目录即发现范围、无需导入 | 面向仓库事件，不含本机交互终端 | 采用 `config/tasks` 自动发现模型 |
| Rundeck | 参数化任务、日志、历史成熟 | 配置/导入和导航层级较重 | 只借鉴任务卡与执行反馈 |
| Kestra | YAML、输入 schema、执行器抽象完整 | DAG、命名空间和集群概念超出单机目标 | 只借鉴 schema 驱动字段，不引入流程复杂度 |

第一轮目标：首屏无所有者元素从 8 类降到 0；空分区从 2 个降到 0；核心操作不增加点击。
