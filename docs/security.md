# LocalFlow 安全设计

## 边界

同一 Ubuntu 服务器的其他用户能够连接回环端口，也可能发现随机端口，所以 `127.0.0.1` 和随机端口只缩小网络暴露面，不代表管理员身份。默认匿名访问只返回任务名称、标签、状态和时间；命令、工作目录、自定义字段、配置和日志由服务端投影删除。

| 能力 | 摘要匿名 | 完整只读 | 管理员会话 | HMAC 客户端 |
| --- | --- | --- | --- | --- |
| 任务摘要 | 是 | 是 | 是 | 只读接口同规则 |
| 完整详情、日志、只读终端 | 否 | 是 | 是 | 只读接口同规则 |
| 提交任务或批次 | 否 | 否 | 是 | 是 |
| 终端输入、中断、确认 | 否 | 否 | 是 | 否 |
| 配置、插件发现、校时 | 否 | 否 | 是 | 否 |

隐藏网页按钮不是授权依据；每个 HTTP 和 WebSocket 入口独立检查身份。

## 浏览器管理员会话

管理员在服务用户身份下执行 `localflow login-code --root <目录>`，读取 `secrets/admin-bootstrap` 的一次性短码，然后在网页输入。交换成功后短码立即原子轮换，响应设置一小时 `HttpOnly; SameSite=Strict` cookie；HTTPS 时同时设置 `Secure`。

响应正文只返回独立 CSRF 令牌，网页保存在内存中。cookie 写操作要求精确匹配当前 scheme 与 Host 的 `Origin`，并用常量时间比较 `X-CSRF-Token`。WebSocket 管理身份要求同源 Origin；匿名完整只读连接即使发送 `input` 或 `resize` 也会被拒绝。

## 程序请求签名

程序先取得 30 秒 challenge，然后使用当前 `secrets/api-key` 对方法、含查询路径、正文 SHA-256、代次、Unix 秒和随机数进行 HMAC-SHA-256。随机数绑定签发时的密钥代次，并在第一次验证尝试时消费，不能重放。

任务进入终态后 API 密钥原子替换并进入下一代。内存只保留上一代密钥 30 秒，且只能配合轮换前签发的随机数；轮换后签发的新随机数不能降级使用旧密钥。调用方仍应在每次请求前重新读取磁盘文件。

## 密钥文件

`secrets` 必须是服务用户拥有的真实目录且不能向组或其他用户开放；两个密钥必须是同一用户拥有、硬链接数为 1 的普通非符号链接文件，且不能含任何组/其他用户权限。新目录使用 `0700`，新密钥使用 `0600`。POSIX 启动检查失败时服务拒绝启动，而不是降级为不安全写接口。

密钥不进入浏览器存储、任务请求、任务环境或事件数据。严格部署使用专用非 root `localflow` 用户，普通同机用户只通过 HTTP 投影查看数据。

## 网络和命令

默认绑定 `127.0.0.1:0`，实际地址写入 `runtime/port` 并设为 `0600`。非回环绑定必须配置存在的 TLS 证书、私钥和至少一个合法受信任代理 CIDR，否则 CLI 拒绝启动；Uvicorn 只接受这些范围的转发头。

任务命令始终以参数数组交给执行器。需要管道或重定向时，用户必须在数组中显式调用 `bash -lc`，因此 shell 风险在任务详情中可见。用户插件是受信任本地代码，没有 Python 沙箱。

HTTP 响应启用 `nosniff`、`no-referrer` 和只允许本地脚本/连接的 CSP。终端块和输入均限制为 64 KiB，尺寸限制为 2–1000 行列；WebSocket 的 await 发送提供传输背压。当前版本未实现按身份的请求速率限制，部署在非回环网络时应由受信任反向代理补充连接数和速率上限。
