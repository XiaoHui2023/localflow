# LocalFlow 需求规格

## 产品目标

LocalFlow 是运行在 Ubuntu 离线服务器上的单机任务调度与执行平台。调用方提交工作目录、命令和元数据，服务负责排队、执行、记录、查询与温和中断。网页提供任务观察、模板化提交、配置管理和运行终端。

## 任务与查询

- RQ-001：提交请求包含名称、工作目录、命令、零个或多个标签，以及可选自定义字段；成功响应立即返回不可重复的任务 ID。
- RQ-002：任务列表可按状态、开始时间、结束时间、日期范围、标签和名称筛选，并提供稳定分页。
- RQ-003：任务详情返回提交快照、队列原因、运行状态、时间、退出状态、自定义字段和日志位置。
- RQ-004：任务状态至少包含 `queued`、`starting`、`running`、`succeeded`、`failed`、`cancelled` 和 `lost`。
- RQ-005：任务的命令、工作目录、标签、变量解析结果和插件输入在入队后形成不可变快照，后续配置修改不改变已有任务。
- RQ-006：当前任务、队列和历史任务在同一工作区内可清楚区分。
- RQ-007：刚结束且当前浏览者尚未确认的任务在行首显示唯一红点；普通任务不显示任何行首状态点。只有鼠标真正悬停任务行才确认并移除红点，聚焦、展开、刷新或重新进入页面均不得误确认。
- RQ-008：运行日志同时流向网页终端和磁盘文件；断线重连可从指定偏移继续读取。
- RQ-009：日志、事件和历史记录的保存期限可配置，清理不得删除仍在运行任务的数据。
- RQ-010：任务运行期间服务进程重启或网页关闭不得终止任务；服务恢复后应重新识别运行状态。
- RQ-011：中断按钮第一次触发等价于终端 `Ctrl+C`；等待可配置宽限期后升级为 `SIGTERM`，再等待后使用 `SIGKILL`。用户无需选择信号。
- RQ-012：同一任务的重复中断请求幂等，并显示当前中断阶段。

## 队列与批量运行

- RQ-020：提交可指定零个或多个互斥键；共享任一互斥键的任务不能同时运行。
- RQ-021：显示标签只用于检索和展示，互斥键单独表达串行规则，避免普通标签意外降低并发度。
- RQ-022：满足运行条件的任务按入队顺序启动；无法启动时记录具体阻塞键与前序任务。
- RQ-023：批量选择多个 case 时，每个 case 的每次运行建立一个独立任务。
- RQ-024：单个 case 可配置运行次数，每次运行可使用自动生成或手工指定的 seed。
- RQ-025：批量提交返回批次 ID 和全部任务 ID，单个任务失败不抹去同批次其他任务的记录。

## 配置、变量与文件同步

- RQ-030：共享工作区包含启动配置、任务配置、插件、脚本和密钥；实例数据目录包含数据库、运行描述、日志、端口、PID、缓存和导出，各目录职责固定。核心不得创建通用 `cases/` 目录；Case 是插件按配置生成或发现的候选项，外部 Case 路径由插件字段显式指定。
- RQ-031：配置支持 YAML、TOML 和 JSON；服务保留源格式，不因读取而重排用户文件。
- RQ-032：磁盘文件是配置的唯一数据源。网页保存使用版本条件写入，外部修改通过文件监视进入网页。
- RQ-033：配置更新先写同目录临时文件并原子替换；保存只受版本冲突与文件能力约束，不受语法或插件可运行性阻断。语法及导入错误必须返回结构化行列并保留原文，运行入口另行拒绝不可解析版本。
- RQ-034：网页发现文件版本已变化时拒绝覆盖，并提供重新载入和差异查看。
- RQ-035：YAML 变量使用 configlib 的合并后整树语义：当前文件及 `!include` 引入的任意键均可按路径引用，`variables` 表兼容为短名别名，并检测缺失与循环。验证插件不得把运行输入或宿主路径隐式暴露为变量，只提供逐任务 `${case}` 与 `${seed}`。
- RQ-036：变量插值必须检测缺失引用和循环引用；预览显示最终命令、工作目录和计算字段。
- RQ-037：模板包含名称、标签、互斥键、工作目录、命令、参数描述和计算字段，可复用并批量派生。
- RQ-038：配置页可设置日志与历史保存期、并发度、端口、匿名读取方式、中断宽限期和时间校准信息。

## 插件与验证仿真

- RQ-040：插件位于共享工作区的插件目录，以 Python 文件形式安装，通过装饰器注册模板提供者。
- RQ-041：插件加载到独立代次；修改文件后新代次只影响新提交，旧任务保留原插件与参数快照。
- RQ-042：插件声明参数模式、界面提示、校验规则、case 发现逻辑和任务展开逻辑，核心不包含验证仿真的专用分支。
- RQ-043：示例验证插件通过自己的 `discover` 合同动态提供 Case：可从插件配置的 `case_names` 生成，也可扫描 `case_directory` 的一层目录与文件；核心不保存或生成 Case。默认不选择 Case，支持直接累加、临时框选、多对象同步编辑和逐 Case 运行次数。
- RQ-044：示例验证插件支持自动 seed 和手工 seed；自动模式为每个展开任务生成并记录确定值。
- RQ-045：插件异常只能使该插件不可用，不能使服务或其他插件退出；网页显示诊断信息。

## 网页与可访问性

- RQ-050：任务页优先显示队列、运行中、刚结束和失败信息；详情按需展开，标签与时间易于扫描。
- RQ-051：模板运行表单由插件参数模式生成，支持 seed、case 多选、次数和通用字段。
- RQ-052：终端使用成熟终端组件，支持尺寸调整、复制、回放、断线状态和流量控制。
- RQ-053：状态不能只依赖颜色；所有操作可由键盘完成，并保留清晰焦点样式。
- RQ-054：网页不依赖公网 CDN，前端资源随安装包提供。
- RQ-055：只读访问者不能看到密钥、完整命令、工作目录、配置内容或完整日志；管理员可查看其权限范围内的详情。
- RQ-056：网页默认使用浅色主题，管理员可切换深色；非敏感显示偏好在同源浏览器本地持久化，并在首屏渲染前恢复。
- RQ-057：网页不重复程序 API 的任务筛选能力，不显示手动刷新按钮；任务自动同步，数量为零的运行中和队列分区不渲染。
- RQ-058：API 使用文档保存在项目目录，说明密钥权限、每请求重读、challenge、签名头、轮换、重试和接口清单；网页不重复提供 API 文档入口。OpenAPI schema 仍只允许管理员会话访问。
- RQ-059：少量一级页面入口在左上角使用纵向导航并保持清晰选中态；页面不得重复显示与当前导航项同义的可见标题，具体删除与保留判断记录在反例目录。
- RQ-065：管理员导航包含“设置”页；主题选择与时间校准集中在该页。时间校准不使用“离线”修饰，进入页面时读取服务器当前时间、持续显示，并以它预填校准输入。
- RQ-066：配置页自动发现固定 `config/tasks` 目录中的任务配置及插件候选项，不显示手动扫描或存储实现文案；字段名称简短、直接且保持旧调用字段兼容。
- RQ-067：可运行任务配置必须以顶层 `plugin` 指明插件；插件选择不在网页或数据库另存。编辑与运行位于同一页面，只有诊断通过的任务配置才显示运行操作。
- RQ-068：配置页面使用可访问的资源树，支持新建、移动、重命名和带确认的删除；服务端拒绝越界、覆盖、陈旧版本和不支持扩展名。
- RQ-069：管理员导航顺序为任务、终端、设置；任务页内的可折叠运行工作区承担配置选择、编辑和任务提交。插件与 API 使用说明只保存在项目目录，不设独立网页入口。

## 接口与事件

- RQ-060：接口具有版本前缀，并提供 OpenAPI 描述和请求、响应示例。
- RQ-061：任务列表、详情、提交、批量提交、确认、日志读取、中断、模板、配置和系统状态均有接口。
- RQ-062：任务事件通过服务器发送事件提供；交互终端通过 WebSocket 提供。
- RQ-063：列表分页使用稳定排序键，默认按创建时间和任务 ID 倒序，翻页期间不重复或遗漏已固定范围内的记录。
- RQ-064：写请求支持幂等键；同一身份、路径和幂等键重复请求返回原结果。

## 访问控制与密钥

- RQ-070：默认监听 `0.0.0.0`，默认端口为 `0`，由操作系统选择空闲端口；启动后检测并打印可复制访问的首选局域网 IPv4 与实际端口，实例状态目录的 `runtime/port` 保存同一地址，不得显示 `0.0.0.0`。可配置固定端口或改回 `127.0.0.1`。
- RQ-071：来源地址不构成管理员身份，包括 `127.0.0.1`。所有未登录网页均按匿名策略投影；浏览器写操作、终端输入、中断、配置、插件和时间操作必须在服务端校验管理员会话，程序接口按 RQ-076/RQ-120 校验 HMAC。
- RQ-072：匿名网页方式可配置为关闭、摘要只读或完整只读；默认摘要只读。
- RQ-073：摘要只读只展示去敏后的名称、标签、状态和时间，不展示命令、工作目录、配置、完整日志及自定义敏感字段。
- RQ-074：浏览器管理员会话使用可续期、`HttpOnly`、`SameSite=Strict` 的签名 cookie，并校验来源与 CSRF 令牌；页面刷新和服务重启后仍可恢复，修改网页管理员秘钥会使旧会话失效。程序 API 密钥不得进入浏览器。
- RQ-075：未登录时设置页显示单行“秘钥登录”；用户从仅文件所有者可读的 `secrets/web-admin-key` 复制秘钥并输入一次。成功后登录控件立即消失且不显示冗余的已登录提示；秘钥不写入 URL、浏览器持久存储、cookie、日志或响应。
- RQ-075A：本地启动器兼容把引导码放入不发送给服务器的 URL fragment，由网页立即交换会话并清除 fragment；程序 API 密钥不得用于网页登录。
- RQ-076：程序接口使用 HMAC 签名，签名覆盖方法、规范化路径、正文摘要、密钥代次、时间和服务器随机数；随机数只可消费一次。
- RQ-077：任务结束后生成下一代程序密钥，原子替换密钥文件；调用方每次请求前读取文件。并发请求使用明确的代次和短暂过渡窗口完成验证。
- RQ-078：首次创建 `secrets` 目录时设置 `0700`，首次创建任一密钥文件时设置 `0600`。后续启动不得审计、修复或因用户修改目录/文件权限而报错，也不得因权限变化重新生成密钥；任务终态触发的 API 密钥原子轮换保留该文件已有模式。
- RQ-079：服务以非 root 专用用户运行。若要让同机其他 Unix 用户读取摘要，使用独立只读组或只读接口，不能与服务写身份共用密钥。
- RQ-080：受信任的离线局域网允许直接 HTTP；配置任一 TLS 文件时必须同时提供存在的绝对证书与私钥路径。受信任代理范围仅在实际使用反向代理时填写且必须为合法 CIDR；文档必须明确 HTTP 不抵御抓包或中间人。
- RQ-081：文档必须明确 IP 地址不能识别具体用户，因此任何来源地址都不自动授权；局域网 HTTP 只适用于可信离线网络，需要传输保密时必须启用 TLS。
- RQ-082：时间输入形成完整有效值后自动提交校准，并显示提交中、成功或失败；不得要求第二次点击应用按钮。
- RQ-083：任务详情在所点击任务行下方展开；再次点击同一行收起，切换任务只展开新的行。
- RQ-084：核心生命周期负责排队、执行、恢复和进程终止；插件定义用户可见状态键、名称、语义和退出码映射，状态定义随任务快照保存，历史不随插件更新改变。
- RQ-085：终端基于 xterm.js 官方组件，按容器尺寸调整并同步 PTY，提供按需搜索和受控链接；终端输出按不可信文本处理，写入仍由管理员权限控制。
- RQ-086：任务可快照一组有界停止动作，动作支持向任务发送信号、写入终端输入或执行专用停止命令，并可等待该动作之后的新输出；控制服务恢复时可重放当前幂等动作。
- RQ-087：管理员具有独立终端页和 HTTP 终端接口，可发送 UTF-8/Base64 输入、常用控制键及尺寸；日志接口按字节偏移立即读取已写输出，人工 Ctrl+C 不自动改变任务状态。
- RQ-088：生产任务只有在主程序退出且 systemd control group 已为空后才进入终态；有界停止动作耗尽后必须对整个 control group 强制清理，停止命令自身超时也不得留下子进程。
- RQ-089：配置支持位于 `config/` 内的公共导入；零公共字段分类为普通配置，任一公共字段触发公共诊断，`plugin` 字段进一步触发插件专属诊断。导入不得越出 `config/`。

## 时间、恢复与运维

- RQ-090：服务器支持管理员输入参考时间；设置页只呈现持续更新的当前时间组件与一个时间校准控件。
- RQ-091：修改系统时间由范围受限的特权辅助程序执行，主服务保持非 root；每次修改写入审计事件。
- RQ-092：持续时间使用单调时钟计算；墙钟调整不能产生负运行时长或破坏队列顺序。
- RQ-093：生产执行器使用 systemd 瞬态服务承接任务进程，任务进程不属于网页服务的生命周期。
- RQ-094：开发和测试可使用 POSIX 子进程执行器，但必须保持相同状态与中断语义。
- RQ-095：服务启动时核对数据库与执行器状态；无法找到且未正常结束的任务标记为 `lost`，不得伪装为失败或成功。
- RQ-096：SQLite 数据库使用 WAL 模式和短事务，生命周期状态只能由任务服务写入。

## 验收边界

- RQ-100：Ubuntu 目标机上的 systemd 生命周期、中断升级、重启接管、文件权限和端口行为必须以真实进程测试验证。
- RQ-101：接口权限测试必须证明匿名身份无法通过页面、HTTP、SSE 或 WebSocket 执行写操作或读取受限字段。
- RQ-102：故障测试覆盖服务重启、插件异常、配置写入中断、日志断线续传、密钥轮换竞态、墙钟跳变和重复中断。
- RQ-103：每条必须需求都映射到负责人、自动测试、判定依据、故障注入和证据位置；未验证项不得表述为已经完成。
- RQ-104：初始化根目录与 Release 解压目录都提供固定的 `config/tasks`、`scripts`、`plugins`、`runtime`、`logs`、`secrets`、`exports` 结构；内置例子至少包含一个一次性随机任务和一个可温和中断的持续任务，发布门验证二者存在且一次性脚本可运行。
- RQ-109：测试阶段 HTML 与 API 响应不得被缓存；已打开页面每两秒检测前端构建修订，修订变化时自动重新加载。
- RQ-110：每个内置插件恰有一份可运行 YAML 示例；使用态只显示插件声明的 `run_fields`，配置专属字段保持隐藏。
- RQ-105：配置资源树的文件名保持同一中性色；无公共字段与含公共字段使用不同图标，诊断错误使用红色警告图标。状态有可访问文本，不依赖颜色单独传意；文件扩展名不在日常界面重复显示。打开无效文件后在工作区内联显示具体错误。
- RQ-106：配置编辑与运行保持在同一文件页面；可运行配置默认进入“使用”，普通参数、公共配置和无效配置默认进入“编辑”。成功反馈不得悬浮遮挡内容，并在短时间后自动消失。
- RQ-107：服务摘要日志、debug 日志和每个任务的即时输出必须全部位于实例状态目录；服务日志按大小轮转，摘要能独立说明关键运行事件，debug 保留模块与排障细节，文件日志不得记录 API 密钥等敏感值。
- RQ-108：运行产生的文件必须有空间上界：单任务输出、任务日志总量、SQLite 主库和 WAL 可配置限额，并保留最小空闲空间；达到任务日志上限不得杀死任务，终态日志和运行描述按期限或配额从旧到新清理，运行中任务不得被清理。
- RQ-111：插件通过经过服务端校验、与前端框架无关的字段契约声明使用态组件；Case 组件的候选字段、逐项次数映射和默认次数均由插件元数据命名，前端不得写死验证插件字段。未知组件、重复字段名、与公共配置字段重名和非法选项使该插件隔离为不可用，不得把任意前端代码注入页面。
- RQ-112：Case 选择不显示搜索框且首次打开全部为零；每行始终显示明确的增加按钮，次数大于零时才显示减少按钮，鼠标滚轮和点击 Case 名称不得改变次数。鼠标、触控或笔按下按钮只立即改变一次，持续按住至少 550ms 后才开始有界连发并分级加速，抬起、取消、丢失捕获或卸载立即停止；键盘激活每次严格改变一次。框选只建立临时作用域，增减同步作用于框选项。成功提交后全部 Case 次数清零。列表在所有视口均为一列全宽紧凑单行，焦点清晰且不得产生页面溢出。
- RQ-113：同一浏览器标签页在一级页面间切换后恢复最近打开的配置、编辑/使用模式和尚未提交的运行参数；主题偏好跨会话保存，任务终端等实时连接不得因隐藏页面而重复建立。
- RQ-114：配置编辑与运行诊断彼此独立。YAML、TOML 或 JSON 语法及显式导入错误在每次编辑后经短防抖重新计算，旧请求必须取消；Monaco 在对应行列显示错误标记，同页下方有界“问题”面板列出错误并可跳回位置，不用弹窗、不切页且不阻止版本化原子保存。资源树把全部配置视为普通文件，不按任务、片段或插件分类。公共字段、插件 schema、路径和运行条件由插件运行页单独诊断并只阻止运行；编辑器允许尚未被插件认识的额外输入。

## 本体资源与交互效率

- RQ-115：质量门禁必须在活跃用户任务为零的全新实例状态目录中，分别测量 LocalFlow 服务进程树的空闲 RSS/CPU，以及完整运行工作台的渲染 CPU、JS 堆、DOM、后台请求和 WebSocket；所有阈值由单一版本化预算文件拥有，任一超限、漏项或把用户任务计入样本均失败。
- RQ-116：任务行在同一行显示名称、标签、状态与当前阶段最重要时间，历史任务必须一眼看到结束时间。展开区不重复终端、任务 ID、结束时间或退出码；字段名完整显示“开始时间”，时间值紧凑且不可复制，用户命令、逐项的 `source` 环境脚本、工作目录、输出路径和插件计算值可点击复制。`variable_sources` 与下划线开头的内部键永不投影；没有计算值就不产生空容器。代码值保持单行并在自身内部横向滚动，悬浮使用中性边界而非蓝色框；复制成功在原控件内用短促勾选动画反馈且不产生布局位移。展开容器在 1440px、760px 和 390px 均须由实际子项决定高度，末项至底边不得超过 12px，任务卡片不得拥有未归属于行或详情的额外高度。
- RQ-117：交互终端只存在于独立终端页，使用 xterm.js、Fit、Search 与 WebLinks 官方组件并保持有界回滚；1440px、760px 与 390px 视口均不得产生页面级横向溢出，终端列数随容器收缩，隐藏页面不保留 WebSocket。
- RQ-118：常用对象操作按完成目标的操作次数验收。选中配置后的重命名为一次直接操作，删除为一次直接操作加一次必要确认；不得先打开无语义价值的通用菜单。降低点击数不得移除破坏性确认、权限校验、键盘路径或可访问名称。
- RQ-119：中止动作使用单一、无外框的语义图标和可访问名称，不叠加“按钮框—圆—方块”等重复轮廓；动作绝对定位于详情右上角，不得增加空白行或详情高度。
- RQ-120：`POST /api/v1/runs` 接受一份内联 `configuration` 和本次 `inputs`，从配置中的 `plugin` 选择插件，使用与网页/配置文件相同的诊断、变量解析和展开逻辑，并在一次事务中创建一个或多个任务。`POST /api/v1/runs/plan` 与配置文件的 `/plan` 入口无副作用返回将生成的任务和待分配值；正式提交支持原子 `Idempotency-Key`。持有磁盘 HMAC 密钥的 signed-client 可使用完整任务查询、日志、HTTP 终端控制以及配置的创建、读取、保存、移动、重命名、删除、诊断、发现、预演和运行 API；每次请求重新取 challenge、读取密钥并签名实际方法、含查询路径和正文。每个插件必须提供配置模型、运行输入模型、运行字段和可直接提交成功的 API 示例；插件描述接口暴露对应机器可读合同，插件文档说明同一合同。
- RQ-121：第一次中止请求必须把活跃任务原子转换为 `stopping`/“退出中”，继续占用并发位与全部互斥键。柔和动作、SIGKILL 和恢复均不得直接伪造取消；只有执行器确认完整进程树结束并取得真实或执行器确认的退出结果后才转为 `cancelled`。未确认时低频退避重试并保持可观察状态。
- RQ-122：交互示例必须持续打印，显示 Ctrl+C，接受并回显普通指令，支持 `status`、`resume`、`quit`，Ctrl+D 关闭输入并直接退出；终端页与 HTTP API 都能发送控制键和文本。
- RQ-123：验证插件只把 `${case}` 与 `${seed}` 延迟到每个任务展开时注入命令及相关字段；同一插件任务任一标签相同时必须通过派生互斥键排队，每个 case 的每次运行仍是独立任务。
- RQ-124：验证插件的多个编译日志和运行日志均为可选配置，省略或空列表不得阻止运行。未配置编译日志时，运行审查和任务结果不得显示编译栏目或编译状态；未配置运行日志时，终态只能是中性的“运行结束”，不得由进程退出码推断验证通过、失败或仿真异常，已有的编译日志可作为详情但不改变该中性状态。配置了运行日志且实际存在时只显示存在的运行日志，按最后 UVM 汇总判定 PASS、ERROR、FATAL，无 UVM 汇总时使用行首锚定 VCS fatal/error 兜底；同时配置了编译和运行日志但运行日志未产生时，才以存在的编译日志表示编译错误。状态标签不带括号或数量，计算信息不显示错误数；插件判定结果和计算信息在任务结束时冻结到任务记录。
- RQ-125：任务信息、事件与终端输出共用一个保留期，默认三天，到期成对清理；运行中、启动中、退出中和队列任务不得按期限清理。容量与空闲空间硬阀仍可提前回收最旧终态输出以保护机器，并必须在元数据中反映输出已不可用。
- RQ-126：服务本体必须可长期运行：调度与退出确认采用事件等待或有上限低频轮询，终端回滚、日志、数据库、WAL、DOM、后台请求与 WebSocket 均有预算或明确生命周期；空闲资源门禁必须排除用户任务并检测 CPU、RSS、JS 堆、DOM、请求和连接泄漏。
- RQ-127：等待队列中，完整标签集合相同且名称相同的任务无条件压缩为一行并显示 `×N`。当等待任务总数超过 20 时，完整标签集合相同的多项任务再折叠为标签组，点击展开内部内容；无标签项不做标签折叠，多标签任务只能属于一个按排序后完整标签集合确定的组。
- RQ-128：验证插件未显式填写随机种子时，插件草稿声明由宿主分配的 `monotonic_unix` seed；宿主在批次入队事务中使用持久化序列原子生成 `max(当前 Unix 秒, 上次值+1)`，同时替换命令和日志字段中的 `${seed}` 并写入任务详情。事务提交后任务名称、命令、目录、标签、互斥键、自定义信息和 seed 均为不可变快照；同秒、并发、重启和墙钟回拨不得产生重复或倒退。名称只使用 case，不包含 seed 或运行序号；显式 seed 同样在创建时冻结。
- RQ-129：项目根目录提供可独立发现的 `skills/`，至少覆盖项目结构、API、配置、插件开发和 Ubuntu 运维。每个技能使用标准 `SKILL.md` frontmatter，按需路由到项目文档，不包含用户名、本机盘符、当前端口、真实密钥或会话材料；Linux 发布压缩包必须保留完整技能目录并由解压后门禁逐项确认。
- RQ-130：验证插件必须提供适合 AI Agent 组合配置的单一机器合同：完整配置 JSON Schema、完整 `inputs` JSON Schema、仅本次运行的组件字段、可直接提交的配置与输入示例、仅 `${case}`/`${seed}` 两个延迟变量以及严格的未知运行输入拒绝。稳定命令、目录、标签、互斥和日志模板写入配置，本次 case、每 case 次数与可选 seed 写入 inputs；同一合同同时驱动 YAML、配置 API、预演 API、内联运行 API 和网页。错误结果对外只显示固定 `ERROR`，不得拼接括号、错误数量或其它计数。
- RQ-131：自测试阶段结束起，每次项目修改只有在完整质量门通过、`main` 推送触发静态 Linux 制品构建、滚动 GitHub Release 成功、版本 tag 指向该次源提交，并从 Release 重新下载校验和与压缩包完成摘要及解压 smoke 后才算交付；不得以本地测试或工作流已触发代替发布闭环。
- RQ-132：Linux 发布物的 PyInstaller 主体、StaticX bootloader 与所捆绑加载器必须在同一个 Ubuntu 16.04/glibc 2.23 兼容基线内完成；不得在较新宿主机二次封装。最终二进制除原生 smoke 外，必须在 QEMU 的 `qemu64`、`core2duo` 与 `Opteron_G1` CPU 模型下完成零参数真实启动探针，任一 `SIGILL`、超时或非零退出都阻断发布。
- RQ-133：公开可执行入口 `localflow` 不接受子命令，只接受声明的共享工作区与实例数据选项。源码与冻结产物都以启动当前目录解析默认值和相对参数；首次直接运行必须无覆盖地初始化缺失配置及隐藏数据目录并启动服务。旧 `init`、`serve`、`status`、`open`、`login-code` 和 `--root` 调用必须被拒绝，最终压缩包必须同时以默认入口和显式双目录完成真实任务闭环。
- RQ-134：每次 Release 必须在 Ubuntu 上直接启动本次最终静态二进制，并分别使用当前稳定 Google Chrome 与 Playwright 对应的 Firefox 完成局域网 HTTP 页面渲染、秘钥登录、Monaco 配置打开、任务提交与详情复制、xterm WebSocket 终端和设置页旅程。两种浏览器均不得出现未预期控制台异常或资源失败；仅允许页面卸载时已取得 200 响应的 SSE 连接产生明确 ABORT。
- RQ-135：离线 Ubuntu 浏览器兼容合同不得只覆盖最新版。生产构建必须只发出面向 Chrome 79、Firefox 78 及以上版本的兼容 bundle 与按实际用法生成的 polyfill，不得保留仅由 2023 年后浏览器支持的必需入口；每次 Release 还必须使用固定 Chrome 84 和 Firefox 78 浏览器镜像直接打开最终静态二进制，完成页面渲染、秘钥登录与 Monaco 配置打开，并断言启动期脚本、资源和未处理 Promise 错误为零。
- RQ-136：首启目录和 Linux 发布包只包含生产 `command` 与 `verification` 插件及各一份匹配配置；marker、interactive、随机数、通用选择器等测试插件、脚本和配置只能在隔离质检目录按需生成，发布门必须同时断言生产项存在与测试项不存在。
- RQ-137：进程启动配置固定为可执行文件旁的 `config.yaml`，仅启动时读取且不进入配置 API、文件监视器或网页资源树。默认文件只写端口、执行后端和三天保留期并原位注释；其它字段使用模型默认值。旧根目录 `localflow.yaml` 或更早的 `config/server.yaml` 在新文件不存在时原样迁移，时间校准继续使用独立运行状态。
- RQ-138：保存、同步、运行等可忽略的瞬时反馈必须位于命名固定通知层，不参与资源树、工具栏、编辑器或运行区布局，不抢焦点，并尊重减少动画设置。浏览器门在反馈出现前后逐项比较主要区域 `x/y/width/height`，任一变化即失败；必须决策的冲突、删除和字段错误仍在所属内容或对话框中持续显示。
- RQ-139：生产 `command` 插件的最小配置只有 `plugin`、`name`、`working_directory` 与参数数组 `command`；默认示例在当前目录写入内容严格为 `hello world` 的 `hello-world.txt`，没有运行时控件。新建配置默认落在以所选插件命名的目录。
- RQ-140：插件可提供有界、只读、无副作用的配置检查钩子，返回稳定名称、标签、解析值、类型、严重级别、说明和显式检查策略。宿主显示完整命令与解析后的工作目录，不得再把字符串命令的首词重复成“命令入口”；验证插件追加 Case 来源、发现数量和审查值。只有声明 availability 的项目在不存在且严重级别为 error 时显示可聚焦叉号，存在、普通信息和未来输出均不显示成功勾或装饰图标。首次打开使用态、保存成功、外部同步和相关输入变化必须取消旧请求并及时重查；错误不能只靠颜色，说明须同时支持鼠标悬浮与键盘聚焦。检查 API 与网页共用同一合同，不创建任务。
- RQ-141：鼠标悬浮提示必须由统一 Portal 组件挂到文档覆盖层，使用命名层级、视口碰撞规避和键盘/Escape 语义；不得嵌在 `overflow` 或局部 stacking context 中。浏览器门必须对真实检查提示验证视口内几何、裁剪祖先为空、五点像素顶层、覆盖 `z-index:40` 故障物、悬浮与聚焦、`aria-describedby`、Escape 消失和零页面溢出。
- RQ-142：点击运行后，图标按钮必须立即进入不可重复提交的受理中状态，HTTP 202 后原位显示短暂成功图标并产生不改布局的状态提示，失败则显示明确错误。任务行在 queued、starting、running 与终态期间使用显式 class 驱动的稳定网格，不依赖旧浏览器不支持的 `:has()`；各可见单元不得重叠或错序。
- RQ-143：每个任务在提交成功时即创建有界 `logs/<task-id>/output.log`，记录受理时间、名称、工作目录和完整参数数组；取得执行位时立即冻结开始时间并记录后端，随后记录进程/单元启动、原始 stdout/stderr、退出码或含异常类型的启动失败。工作目录不存在、命令不存在和 systemd 启动失败也必须保留非空日志、开始/结束时间、真实失败状态和日志大小。默认 `execution.backend: auto`：可用时采用用户 systemd 保持重启接管，否则明确告警并回退 subprocess，使直接解压运行的基本任务可执行；显式 `systemd` 不静默降级。
- RQ-144：公共配置与插件的 `command` 同时接受非空字符串和非空字符串列表。示例、首启配置、文档与插件 API 示例优先字符串；未设置 `shell` 时从服务进程 `$SHELL`、运行用户 passwd 登录 Shell、`/bin/sh` 依次选择，并规范化为 `[<shell>, -ic, <原文>]`，让所有插件统一加载 `.bashrc`、`.cshrc`、`.zshrc` 或对应交互启动配置中的函数、别名和环境。可用 `shell` 显式覆盖；`shell` 与参数列表同时出现必须拒绝。交互启动文件即使执行 `cd`，用户命令前仍须回到已冻结的绝对任务工作目录。列表保持精确 argv，不得逐字符展开或隐式拆词。空白、NUL、空列表和空参数必须拒绝，所选 Shell 与规范化 argv 必须进入预演、检查、日志和不可变任务快照。
- RQ-145：任务页运行工作区的虚拟化资源树必须同时呈现 `config/`、`plugins/`、空目录和软链接身份，支持新建文件/目录、拖放移动、行内重命名、复制、剪切、粘贴、删除、标准键盘快捷键与直接工具栏。插件 `.py` 保存前编译，配置保存前解析诊断，冲突不覆盖外部内容；移动、复制或删除不得让原本可解析的导入静默损坏。
- RQ-146：整个 `config/`/`plugins/`、其中目录和单文件均可为软链接。读写跟随目标但不替换链接；移动/重命名移动链接目录项；复制重建同一链接文本；删除只删链接。资源 HTTP 路径词法限制在两个根且禁止绝对路径和 `..`；只允许通过所有者预先建立的链接访问外部目标。Linux 门必须覆盖文件、目录及整根链接和循环链接，不得无限递归。
- RQ-147：磁盘到网页与网页到磁盘的同步同时覆盖配置和顶层插件。原生 watcher 之外必须有不高于一秒的有界内容校对，以覆盖不跟随嵌套软链接的实现；事件应携带实际变化路径，只刷新命中的当前文件。外部删除、无效配置和插件代次变化均要刷新资源树；编辑器无本地修改时自动刷新，已有未保存修改时必须保留内容并提示冲突，页面不得要求手动扫描或刷新。
- RQ-148：终端 WebSocket 必须实施应用层背压：单块不超过 64 KiB，xterm 完成本块写入后 ACK，服务端收到 ACK 才发送下一块。切页/卸载先解除回调，再释放 socket、观察器、动画帧和 emulator；高速输出、反复切页、断线和宽窄尺寸门禁不得产生控制台错误、无限缓冲或隐藏连接。
- RQ-149：LocalFlow 控制器必须抗误关：Ubuntu 忽略 SIGINT、SIGTERM 与 SIGHUP；管理员网页退出和 systemd `KillSignal=SIGUSR1` 是显式停机入口。显式停机停止新请求，取消队列并按协议清理全部运行任务，确认无进程树后才退出。无法清理时必须保持控制器持有任务，不得杀控制器伪报成功。

- RQ-179：左侧全局导航只保留“配置”折叠入口，不得用缩进按钮伪造二、三级导航。配置面板展开后，在其资源栏标题区以同级“资源 / 常用”标签页原位切换资源树与常用列表；面板收起时标签页随面板隐藏。标签页使用 `tablist`/`tab`/`tabpanel`、唯一选中态和左右方向键、Home、End 键盘语义。列表不是文件树，按“已收藏”“最近使用”显式分组，收藏组始终在最近组前；组内按最近一次成功提交时间倒序，未运行过的收藏按最近收藏顺序补位。每项仅以完整 `config/` 相对路径作为可见及可访问标识，不显示可能重复的配置名和标签；任意长路径须在条目内部完整换行且不得横向溢出。服务端记录所有真实提交过且仍存在的 YAML，网页刷新后仍可见；标题区星标只管理当前浏览器至多 100 项的个人收藏。网页内明确的移动/重命名必须迁移历史与收藏路径；外部位置变化无法可靠建立新旧身份时，不猜测匹配，自动丢弃旧收藏。工作区刷新应清理失效路径，点击与读取之间再次移动或删除而返回 404/410 时也须静默剔除该收藏、重新同步列表并保持当前工作台可用，不得抛出未处理异常或导致页面退出。切换资源/常用视图不得卸载编辑器、丢失当前配置、草稿、运行模式或输入。
- RQ-180：服务文件日志属于非关键观测通道，不得阻断控制器停机、任务清理或运行身份文件删除。`logs/service` 在运行中缺失时，日志处理器须在自己的写入边界恢复目录和文件；目录被文件占用、权限暂不可用或磁盘探测发生竞态时，文件日志应限频告警并降级到控制台，后续条件恢复时自动恢复写入。最终 Linux 冻结程序门必须在运行任务仍存活时删除该目录，再证明网页退出返回 202、任务进程树清空、控制器退出、PID 文件删除、日志目录恢复且无 Python logging traceback。
- RQ-186：公共入口不设子命令，以 `--workspace` 与 `--data` 作为规范路径选项。两者的相对值以启动当前目录解析；前者默认当前目录，后者默认当前目录的 `.localflow/`。`--config-root` 与 `--state-dir` 作为隐藏兼容别名映射到同一目的；新旧拼写同时出现且解析到不同目录时必须拒绝启动。源码安装和冻结程序遵守同一规则，不得把可执行文件目录暗中当作动态数据目录。
- RQ-187：多个实例可读取同一工作区和密钥，但数据库、日志、端口、PID、缓存、任务描述和恢复历史只能写入各自数据目录。一个数据目录同时只能由一个控制器占用；systemd 任务单元身份还须包含数据目录命名空间，避免复制历史后同主机冲突。
- RQ-188：任务相对 `working_directory`、插件根上下文、配置 include 和可用性检查只以工作区为基准，不能因数据目录改变而改变。保持数据目录后重启只恢复该目录的历史；改用空数据目录等价于新实例。
- RQ-189：实例数据带格式版本。可识别旧版本按向前兼容迁移；损坏或不兼容的旧动态文件可隔离后重建，配置与密钥不得移动或删除；高于当前程序的格式必须拒绝降级启动并保持原数据不变。旧单根部署可显式 `--data .` 或兼容的 `--state-dir .` 继续读取原历史。
- RQ-190：SQLite 数据目录不得由多个主机共享。共享工作区配置文件的网页写入继续使用版本条件与原子替换，但不承诺跨主机分布式锁；冲突或同时编辑同一文件必须可诊断，不能影响各实例任务状态。
- RQ-191：管理员网页退出一经返回 202，应用必须立即广播控制器级退出事件，使所有 SSE 流和终端 WebSocket 在服务端主动结束；浏览器也必须关闭自己的 EventSource 并停止状态、任务和 UI 版本轮询。不得等待刷新、关闭页面或客户端 Ctrl+C 才完成 Uvicorn 连接排空。即使没有运行任务，保持真实浏览器页面和事件流打开的 HTTP 服务也必须在有界时间内退出，且退出后的页面不得自动重连；ASGI 服务器另设有限的 graceful-shutdown 外层期限，防止未知连接缺陷无限阻塞 lifespan 中的任务清理。
- RQ-192：所有生成命令任务的插件共享可选 `source` 公共字段，接受一个路径、非空路径列表，或由 `path` 与 argv-safe `arguments` 组成的单项/列表，且只允许字符串命令。相对路径以冻结后的任务工作目录解析；参数按独立 argv 元素引用，不允许插件猜测 `-env_path` 等工具专属参数。核心必须在该任务自己的已选/自适应交互 Shell 内依次 source，全部成功后执行用户原始命令。source 产生的环境、函数和别名只可由该任务及子进程继承，不得修改控制器或泄漏给并行任务。sh/dash 使用点命令，其余支持的 Shell 使用 source；运行审查与任务详情逐项显示冻结后的完整 source 调用、仅在运行前脚本路径缺失时标错，任务终端在命令前逐项记录实际加载路径及参数，任务命令展示不得混入核心注入的 cd/source 包装。直接任务 API、command、verification 和第三方插件走同一合同。
- RQ-193：插件运行信息是内容驱动的紧凑结构化列表，不是填满工作台的卡片布局。外层全高 Flex/Grid 不得把剩余高度分配给检查网格或其隐式行；普通单行 command 检查项在 1440px 与 760px 门中高度不超过 44px，列表项只按自身元素数和内容换行自然增高。运行检查、复制值和任务数组须由独立语义组件及归属样式维护，禁止依赖综合样式表中的偶然级联。浏览器门必须先在真实 command 配置上测量每行边界盒，再注入恢复默认 Grid 拉伸的故障样式并证明同一几何判据能够拒绝。
- RQ-181：从“终端”切回“任务”时不得卸载并重建资源树、Monaco、所选配置、草稿或运行输入；任务工作台保持挂载但不可见，终端页仍须卸载以同步释放 xterm、观察器和 WebSocket。Edge 浏览器门须从导航点击测量到连续两个绘制帧，耗时不超过版本化预算 250 ms，并证明工作台 DOM 身份保留、终端 DOM 与连接已消失。插件审查的 `code-list` 必须保持数组边界，每项是独立复制面且宽度至少等于所属值列减 1 px；不得继承通用带标签网格的固定标签列宽。
- RQ-182：`execution.max_concurrency` 默认值为 `unlimited`，不以 CPU 数或固定任务槽位阻塞互不互斥的任务；旧配置值 `auto` 必须作为 `unlimited` 的兼容别名，避免升级后保留旧的 CPU 派生上限；显式整数 `1..4096` 仅作为管理员主动限流。状态 API 同时返回配置值和结算结果，无上限时明确返回 `unlimited`。生产任务各自使用独立 systemd unit/cgroup，LocalFlow 不施加未声明的 CPU、内存或 I/O 限额；默认只有重叠互斥键才持续排队。调度器须用有界、可推进的游标分批接纳大队列，批次边界不得变成持续并发上限；至少 500 个前置互斥任务不能永久饿死后方独立任务。退出、恢复和互斥键归属须跨存储分页覆盖全部活动任务；终态日志保留总量不得反向构成启动门槛。质量报告须区分软件接纳、控制器开销和有限硬件上的 CPU、内存、I/O 争用，不得把“无软件槽位上限”表述为无限算力或性能不受物理资源影响。
- RQ-183：任务详情中的任意数组值必须保持数组语义，每个元素占独立一行、独立完整宽度代码面与复制目标，不得 JSON 化或拼接成单行；须以真实完成任务验证元素数与 owner/row/value 几何。详情时间字段使用与其它字段一致的纯文字“开始时间”，完整值保留在语义化 `time[datetime]` 与悬浮信息中，不添加孤立装饰图标。
- RQ-184：网页资源评估须包含初始兼容入口，而非只测空闲 CPU/RSS。Monaco 编辑器与 worker 只能在进入编辑或冲突界面时按需加载，普通任务/运行界面不得下载该分包；构建后的旧浏览器初始入口 gzip 大小须由机器从最终资产复算并不超过 0.3 MiB，收据声明值不得自行伪造。
- RQ-185：完整权限任务详情与列表必须返回 `log_updated_at`，其值与 `log_size` 来自同一次日志文件元数据快照；日志不存在时为 `null`，实际追加字节后更新并跨控制器重启保留。终端 WebSocket 的每个 `output` 与 `caught_up` 帧也携带服务端日志时间；初始/分段回放追平前不得显示活动时长，以免把正在渲染的旧字节误解为任务刚输出或已卡住。左侧所有终端条目不得显示活动时间；右侧仅为当前选中、已收到 `caught_up`、仍处于 starting/running/stopping 且已有输出的终端渲染一个语义化 `time[datetime]`。距最后输出不足 5 秒时不显示，之后每秒实时推进；一分钟内显示 `Ns`，一小时内显示 `Nm Ns`，一天内显示 `Nh Nm`，更长显示 `Nd Nh`，不添加“最后输出”“前”等重复可见文字。该时间与任务名必须在一个不换行的标题行内左右排列。终态历史和没有输出时均不渲染该元素、占位符或空状态文字。悬浮说明提供本地化完整时间，可访问名称说明时长含义。活动时间保持中性，不用危险色或“卡死”结论。百万行回归必须同时证明初始历史只读取末尾 4MiB、单块不超过 64KiB、Python 峰值分配有界，全文检索仍按固定块和结果上限运行。xterm 选区必须支持 `Ctrl/Cmd+C` 与指针位置的实色、可键盘操作右键菜单；菜单只复制准确选区，不得在远离选区的工具栏生成临时复制按钮。
- RQ-163：停止动作可显式启用基于新增终端输出的进展延长。启用时 `timeout_seconds` 是无新输出的静默窗口，且必须提供不小于它的 `max_timeout_seconds` 绝对上限；新增字节只重置静默窗口，不得越过硬上限。真实 systemd/PTY 门必须分别证明持续正常清理超过原静默窗口仍以退出码 0 结束，以及持续刷输出但永不退出的程序在硬上限后进入 `sigkill` 并清空 cgroup。默认动作不得自动启用或猜测进展。
- RQ-164：任务结果等待通道临时失败时，控制器必须重新探测执行器所有权；只要进程树仍存活就保持非终态并有界退避重试，不得标记 `lost` 或释放并发/互斥。显式服务退出必须先关闭调度入口并等待所有已派发启动完成 systemd 所有权交接，再建立完整活动任务快照；总期限到达后必须取消仍在运行的柔和停止序列、原子记录 `sigkill` 阶段、清理完整 cgroup，并持续确认单元明确进入 `inactive`、`failed` 或 `not-found` 且取得退出结果后才允许控制器结束。`activating`、`active`、`reloading`、`deactivating` 等非终态均必须继续视为进程树仍受管，不能依赖 `systemctl is-active` 的布尔退出码提前放行。签名程序 API 必须同时提供任意 UTF-8/Base64 终端字节、常用控制键、PTY resize 和按偏移日志；管理员网页另由带 ACK 的背压 WebSocket 驱动。终态写入须返回冲突。
