# 用户需求总账

本文件记录产品意图；可测试的硬要求以 [requirements.md](requirements.md) 的 RQ 条目为准，设计失败模式进入 [ui-counterexamples](ui-counterexamples/README.md)，接口、配置、插件、终端、停止、安全和运维细节分别进入对应专题文档。未经用户明确确认，不上传、不发布 Release。

## 产品与部署

- 目标是 Ubuntu 上的本地任务代运行服务。共享工作区固定发现配置、插件、脚本与密钥且可被多服务器复用；每个实例用独占数据目录保存运行时、日志、缓存、端口和历史；Case 候选由所属插件动态生成或发现，核心不创建通用 `cases/`；配置修改实时生效，无扫描按钮。
- 网页默认监听局域网，端口随机或固定可配；启动输出可复制的局域网 `IP:端口`，而不是 `127.0.0.1` 或 `0.0.0.0`。客户端地址不作为管理员身份。未登录网页只能获得匿名投影；设置页可从所有者专读文件复制网页秘钥登录一次，成功后长期保持且不再显示登录控件。程序 API 使用独立的所有者可读轮换密钥和请求签名，调用方每次请求前重读密钥文件。
- 长任务不随网页或服务重启被突然杀死。停止先模拟人在终端的 Ctrl+C/输入/等待协议，再逐级升级，并最终清理整个任务进程树。终端同时支持实时读取、输入字节和控制键，API 提供同等能力。
- GitHub 最终要有静态打包 Release 与自动发布工作流，但测试阶段持续本地改进；用户说可以发布后才上传。
- `localflow` 是零子命令入口，规范选项为 `--workspace` 与 `--data`。不传参数时以当前目录为工作区、以 `./.localflow` 为实例数据；指定不同数据目录即可分离服务历史，指定同一工作区即可复用配置、插件和密钥。旧 `--config-root` 与 `--state-dir` 仅兼容已有脚本。

## 任务、队列与 API

- 申请包含名字、多个标签、工作目录、命令和自定义信息，返回任务 ID。命令优先使用字符串并兼容精确参数列表。API 支持进行中/完成/队列列表、日期与开始/结束/运行时间及标签筛选、详情、日志字节偏移读取和终端控制。
- 插件可定义任意显示状态和完成判定，不限成功/失败。多个互斥标签可形成串行队列；仿真每个 Case/每次运行各占一个任务。
- 单个 API 请求可直接携带配置和本次输入，由配置的 `plugin` 选择插件并创建一个或多个任务；网页运行、配置文件和 API 共用同一插件模型。持有磁盘 HMAC 密钥的程序客户端可以完整查询任务和日志、执行 HTTP 终端控制，并完成配置的创建、读取、保存、移动、重命名、删除、诊断、发现与运行。每次请求重新取 challenge、读取密钥并签名实际方法、含查询路径和正文。每个插件必须随附机器可读 API schema、可直接提交成功的示例和简明文档。

## 配置与插件

- 配置与运行合并进“任务”页的可折叠运行面板；唯一开关固定在左侧一级选项卡附近，以显眼的方向图标和“配置”文字呈现。宽屏展开后的配置工作台位于任务左侧并与任务并排；中窄屏不再把两个不完整工作面上下堆叠，展开时只显示配置，收起后任务立即占满可用区域。窄屏时配置内部再把资源树置于编辑器上方。当前文件名旁就近提供带文字的编辑与运行操作；配置通常复用，选中可运行配置即进入使用态，编辑为次要模式；折叠或切换一级页面后恢复文件、模式和未提交参数。
- 全局侧栏只用“配置”控制工作区折叠，不再显示缩进的二、三级开关。配置展开后，在资源栏自己的标题区用同级“资源 / 常用”标签切换资源树和常用列表；收起配置时标签随面板隐藏。常用列表以条目而非文件树呈现所有曾成功提交的运行 YAML，并分为“已收藏”和“最近使用”：收藏恒在上方，各组按最近使用排序。每项只显示完整的 `config/` 相对路径，不再显示可能重名的配置标题或标签；长路径必须完整换行而非截断。当前配置可用标题区星标收藏，个人收藏在浏览器中持久保留。网页内明确移动时迁移收藏；外部位置变化无法确认新身份时直接丢弃旧收藏。刷新或点击时遇到文件已经移动/删除不得让页面报错或退出，只清理失效条目并继续工作，用户可在新位置重新收藏。
- 从终端切回任务不得重建整个配置工作台而产生可感知停顿；资源树、编辑器、草稿和运行输入保持同一状态，终端连接仍须在离开时关闭。点击到两个后续绘制帧的耗时必须进入版本化浏览器预算。插件审查中的列表值必须逐项占满所属值列，不得因复用带标签的通用网格而缩成异常窄列。
- 终端列表只显示任务名称与标签，不逐项显示最后输出时间；用户选择仍在运行且已有输出的终端后，右侧标题同行显示一个实时推进的紧凑时长。5 秒内隐藏，一分钟内用 `24s`，数分钟用 `5m 12s`，小时和天只保留相邻两级单位；没有输出或已经结束就不显示。该值必须来自日志本身而不是任务状态更新时间，不能擅自把静默解释为卡死；精确本地时间通过悬浮和可访问语义保留。百万行日志仍只加载固定尾部窗口并流式检索，浏览器和服务内存不得随总行数增长。
- 服务器可有大量任务。默认不设置 LocalFlow 任务槽位上限，旧配置中的 `auto` 也不得继续按 CPU 数阻塞任务；只有用户明确填写整数或任务互斥键时才允许排队。每个生产任务使用独立 systemd unit/cgroup，状态、终端、日志、信号和清理不能串扰。大批阻塞任务不能遮住其后的独立任务，调度扫描必须有界且可推进，但扫描批次不得成为持续并发上限。必须分别评估调度吞吐、控制器 CPU/RSS/数据库、网页最大任务集、大日志窗口及任务进程归属；无软件上限不代表有限硬件能提供无限算力，不得把物理资源过量争用误称为“所有任务性能不受影响”。
- 任务结束后的详情仍须保持结构化显示：数组每个元素单独一行、占满值列且可分别复制；开始时间与其它字段统一使用文字标签，不用孤立图标。
- 网页整体性能评估还须覆盖首次加载包。重型 Monaco 编辑器不能阻塞普通任务/运行页面的首次访问，只有进入编辑/冲突时才加载，并以构建产物 gzip 预算及真实浏览器资源时序门禁防回退。
- 配置区像以 `config/` 内容为根的资源管理器，不投影额外的 `config`/`plugins` 顶层节点；自动双向同步，支持空白新建文件与目录、拖放移动、显式行内重命名、复制/剪切/粘贴、删除和编辑，并兼容整个根、局部目录和文件软链接而不破坏链接。单击/双击目录只负责选择与展开，不得隐式重命名；重命名支持 Enter 提交、Esc 或失焦取消。所有配置文件在资源树中性质相同，不用模板或语义分类图标制造隐含类型。每个文件独立保留未保存草稿，文件和折叠父目录显示圆点；切换文件再返回不得丢失内容，成功保存才清除状态。
- 配置使用 configlib 的显式导入和变量层，支持 YAML/TOML/JSON。编辑器只内联诊断语法与导入，错误不弹窗、不阻止编辑或原子保存，并允许尚未被插件认识的额外输入。插件字段、目录与完整命令等运行诊断只在插件运行页由对应插件管理；不通过则禁止运行，但不反向限制文件保存。
- 插件放入目录，通过 Python 装饰器动态注册，拥有开发文档、使用说明、配置模型、运行组件、发现钩子、状态和展开逻辑。每个插件只配一份实际 YAML 及必要脚本/Case；内置命令、验证、状态标记和交互退出示例。
- 验证插件自己生成 Case 候选：可用配置内 `case_names`，也可扫描 `case_directory` 的一层目录与文件（目录名和文件去最后后缀作为 Case）；LocalFlow 核心不创建通用 `cases/`。每个 Case 次数独立且进入页面与成功提交后全为零；具名加减按钮短按只改变一步，短按释放后跨过 550 ms 阈值也不得继续变化，零值不显示减号，按住 550 ms 后才开始有上限地加速，释放、取消、窗口失焦或失去指针捕获必须停止。Case 名和滚轮都不改变次数；框选只建立批量作用域，点击外部取消。种子默认空，可留空随机或填固定值。用户命令是任意工具指令，插件只提供 `${case}` 与 `${seed}`，均可按需使用或完全不用；其它变量来自 include 合并后的 YAML 配置树，插件不得强制占位符、泄漏运行输入或猜测并追加参数。
- 验证插件的编译日志和仿真日志都可不填写；空配置不显示对应空栏目。没有编译日志配置就没有编译相关状态；没有仿真日志配置时终态只显示中性的“运行结束”，不能仅凭退出码声称验证成功或失败。
- 最终命令必须在配置解析出的工作目录中真实执行。工作目录正确性不能只靠打印 `PWD`，还要用相对 `mkdir`/文件副作用同时证明产物出现在目标目录、没有落入 LocalFlow 运行根。任意插件的字符串命令默认自适应运行用户的 bash/csh/zsh/fish 等登录 Shell，加载对应交互启动配置中的快捷函数和别名，也允许显式覆盖；启动脚本中的 `cd` 之后必须再次恢复冻结工作目录。
- command、verification 及其它产生字符串命令的插件统一支持任务级 `source` 路径列表；不接受单个字符串、完整 source 命令或参数对象。脚本在该任务自己的同一种 Shell 中按列表顺序加载后才运行命令，环境变量、函数和别名只影响此任务及子进程，不能污染控制器或其它并行任务；相对路径跟随任务工作目录。带参数的初始化操作由用户封装进列表所指向的脚本。精确 argv 不支持 source 并须提前诊断。运行配置和任务详情逐项显示脚本路径，终端在命令前记录实际加载项，但任务命令仍只显示用户原始命令。
- YAML 的网页诊断与实际任务创建使用同一份变量结算结果和字段类型合同。标签等任务字段若在结算后出现 `null` 或非法元素，必须在点击运行前进入可调试的配置无效状态；插件未使用的自定义空值不影响任务，可选公共字段写成 `null` 按未提供处理。
- 正式首启和发布只保留验证仿真与简易命令两个插件，每个插件目录只有一份对应配置；其它状态、交互和随机示例只用于隔离质检，不进入用户目录。简易命令只配置名字、工作目录和命令，默认在当前目录写 `hello world` 文件。
- 服务启动配置独立放在可执行文件旁的 `config.yaml`，只在启动时读取，不显示在任务页运行工作区；默认字段少且就地注释。时间校准等动态状态不放入启动配置。
- 使用配置时显示插件提供的只读审查结果，例如实际工作目录、Case 来源和完整命令，不重复显示命令首词。插件显式声明哪些输入要检查存在性；只有缺失时显示叉号，正常和普通信息不显示勾。标签逐项显示为不可复制词缀；编译/运行日志等列表逐项显示为独立行、代码块和复制目标，不拼成一块。验证自定义文本和日志在这里保留 `${case}`/`${seed}` 模板，任务创建时才冻结。保存、外部同步、直接或间接 include 变化或插件变化后即时重查，Case 次数和 seed 输入不得改变静态审查；叉号悬浮和键盘聚焦均可读原因。

## 网页信息架构与交互

- 默认浅色，可在设置切深色并记忆。少量一级入口在左上纵向排列，导航容器只包住实际入口，不画满空白高度。顺序为任务、终端、设置；运行是任务页内一键开合的工作面板，插件和 API 不占网页入口，说明留在目录 Markdown。
- 页面自动刷新，测试阶段自动检测新前端构建并重载；无手动刷新、无固定绿色浮层、无只读摘要等无动作价值内容。没有数据的任务分区不显示。
- 保存、运行和同步的短提示浮在独立通知层，出现和消失都不能挤动、缩放或移动资源树、工具栏、编辑器与运行控件。
- 删除测试：与导航同义的页面标题、重复说明、“修改 YAML/配置格式/磁盘”等无决策价值文字删除。说明性长文放文档。点击数/操作数是质量指标，常用动作直达；渐进式披露只隐藏低频复杂度。
- 设置页只有统一排版的主题和时间校准。时间控件动态显示服务器时间，修改有效值后自动提交，不再点击应用；名称和控件保持一行。
- 任务行紧凑显示名称与标签同一行、状态和一眼可见的关键时间；普通任务没有行首点，只有新完成任务显示行首红点，且仅鼠标悬浮确认。点击行向下展开，再点收起。详情没有终端、任务 ID、结束时间或退出码；显示开始时间、用户命令、逐项的 source 环境脚本、工作目录、输出路径和插件计算信息，所有目标视口都不得留下详情底部空白。
- 队列中同标签集且同名任务始终显示为一行 `×N`；队列超过 20 项时，同标签集任务再折叠为可展开分组。验证任务以 case 命名；空 seed 在入队事务中按持久化 Unix 序列生成，单 Case 多次、并发、重启和校时后仍不重复且递增，并显示在详情。
- 详情值为单行可复制代码块，自身横向滚动，普通悬浮不出现蓝框；常驻复制图标在点击后于原位切换为勾和成功表面，不弹出脱离目标的提示，也不改变布局。详情没有底部空白。中止用单一无外框语义图标，不能出现方框套圆圈套方块。
- 终端独占一级页面，使用成熟 xterm.js 与 Fit/Search/WebLinks。任务切换、控制键、命令输入和搜索必须紧凑；终端占满剩余空间，宽窄视口都没有页面级横向溢出，离开页面关闭连接。
- 任务进入完成、失败、已停止或丢失等终态后仍保留在终端页，并继续以只读 xterm 回放保留期内的历史输出；不得再显示或接受输入、Ctrl+C、Ctrl+D 与 resize。历史查看沿用成熟查找条，支持 Ctrl+F、匹配计数、上一个/下一个、区分大小写、全词、正则以及跳到开头/末尾。
- 实时与历史终端的输出都可选择并用 Ctrl/Cmd+C 复制；实时终端仅在没有选区时才把 Ctrl+C 解释为中断，复制日志不能误伤任务。
- Case 选择始终是一列长而扁平的全宽行，按顺序纵向扫描，不随宽屏变成多列。鼠标进入/离开和键盘聚焦反馈必须即时、克制且连贯；聚焦、Case 名和滚轮都不能改变次数。大量 Case 仍要保持低 DOM、CPU 与输入延迟，并保留框选以及具名增减按钮的批量步进。

## 文档、学习和质量闭环

- 根目录 `skills/` 提供给其它 AI Agent 的项目结构、API、配置、插件开发和 Ubuntu 运维入口；只包含项目相对事实，不包含私人信息，并随 Linux 压缩包一起交付。
- 项目内保留架构、配置、插件、API、安全、停止、终端、日志/资源、部署和例子文档；插件目录有面向使用者与开发者的说明。网页避免承载说明书。
- 所有用户反馈都进入本总账、RQ、反例或技能，不依赖聊天记忆。用户否定已展示结果时撤销相关通过声明，强制联网搜索、Find Skills、资料分析/必要下载、成熟方案比较、失败样本固化和真实浏览器复验。
- 网页不能只在开发机 Edge 中通过；每次最终 Linux 发布物都要在 Ubuntu 的 Google Chrome 与 Firefox 中实际完成登录、配置、任务、复制和终端操作，并把控制台错误与资源失败作为发布阻断项。
- 离线环境的 Chrome 与 Firefox 可能长期不升级；支持声明必须写清最低版本，并用固定旧版本浏览器直接验收兼容 bundle，不能以最新版同品牌浏览器通过代替。
- 质量覆盖功能、权限、进程稳定与残留、配置诊断、插件扩展、API、日志及时性与保留、网页宽窄交互、点击数、可访问性、视觉密度、构建新鲜度和应用自身 CPU/RSS/JS 堆/DOM/请求/连接。门禁必须能拒绝故意坏样本，不能等用户发现才补测试。
- 控制器常驻后不能被终端 Ctrl+C、普通 SIGTERM 或终端断开轻易关闭。发布包提供独立停机 shell，只有它或 systemd 显式停机才收敛队列与全部任务进程树；无法确认干净时不得杀控制器伪报完成。
- 服务日志目录临时缺失或不可写不能阻断退出；程序应自动恢复 `logs/service`，无法恢复时只降级到控制台，并继续完成任务进程树清理、运行身份文件删除和控制器退出。
- 网页退出不能停在 Uvicorn 的 `Waiting for connections to close`，也不能要求刷新网页或再按 Ctrl+C。退出登记后由服务端主动关闭事件流与终端 WebSocket，再进入任务/cgroup 清理；没有运行任务但浏览器仍开着的真实服务也必须有界退出。
