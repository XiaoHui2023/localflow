# 网页冗余反例目录

本目录记录 LocalFlow 已遇到的界面废话，防止后续改版重新引入。判定方法不是“看起来简洁”，而是逐项回答：用户是否需要、删除后是否影响理解或操作、是否已有另一个元素承担同一语义。

## 导航与标题

| 反例 | 为什么是废话 | 正确处理 | 回归检查 |
| --- | --- | --- | --- |
| 选中的“任务”导航旁再次显示大标题“任务” | 导航已经给出当前位置；标题没有增加范围、状态或动作 | 删除可见标题，直接进入任务分组或空状态 | 当前导航仍有文字与选中态；页面中没有同名可见标题 |
| “配置”导航内再显示“配置”标题 | 左侧导航和配置文件列表已经建立上下文 | 删除重复标题，保留文件路径和保存动作 | 文件列表、当前文件与保存仍可识别 |
| “API”导航内再显示“API”标题或版本摘要 | 导航已命名页面；版本不是查接口时的操作信息 | 两者都删除，直接显示端点分组 | 页面没有 API 标题和版本摘要；端点仍可查阅 |
| 每个端点重复一遍密钥签名流程 | 同一协议被复制后难维护，也淹没端点差异 | 页面顶部只放一个默认收起的“调用说明”，端点各自只描述参数和响应 | 调用说明覆盖完整签名闭环；端点卡不重复 |
| “编辑 / 使用”常驻双选项卡 | 配置多数时间只用于运行；双选项卡制造第二层导航 | 有效配置直接显示运行控件，只保留简短“编辑”动作 | 默认无编辑器；按钮名称能预测结果 |
| 运行页再次解释插件和“无需参数” | 删除后不影响运行，且会把主动作推远 | 说明放入 `plugins/README.md`，无运行字段时保持内容区为空 | 运行区仅出现插件声明的 `run_fields` |
| Case 路径、命令和互斥键都做成运行控件 | 稳定配置被反复确认，容易误改 | 仅 Case、逐 Case 次数和 seed 出现在使用态 | 配置专属字段只在 YAML 中 |
| 新建、铅笔、删除三个等权图标挤在资源树标题 | 铅笔含义不清，破坏性动作过于显眼，按钮尺寸也不一致 | 新建保留一级；重命名、删除收进省略号菜单 | 图标控件统一 32px，文字菜单说明动作 |
| 实时时钟和时间输入并排重复展示同一时间 | 两个数值造成核对负担 | 一个会自行走时的 `datetime-local` 控件，修改后自动提交 | 页面只有一个“时间校准”标签和一个时间值 |
| “配置”入口实际同时负责日常运行 | 标签只描述低频编辑，用户找不到主要动作 | 改名为“运行”并放在任务之后 | 导航顺序固定为任务、运行、终端、设置 |
| 文件名用紫/绿/红区分类型与结果 | 大面积彩色文字制造噪声，选中态可读性不稳 | 文件名统一中性，只让不同形状的图标表达状态 | 灰度下仍能由形状与可访问名称识别 |
| “修改 YAML”“加入队列”重复实现词与结果文案 | 文件格式和调度实现不影响当下决定 | “编辑”文字动作；运行用带提示的 Play 图标 | 扩展名和 YAML 文案在使用态为零 |
| 插件与 API 各占一个常驻导航入口 | 日常操作不依赖它们，文档已存在且更适合开发者查阅 | 删除网页入口，保留 `docs/plugins.md`、`docs/api.md` | 导航减少两个目的地，文档测试继续存在 |
| 配置与运行各占一页并再次选择模板 | 文件已经声明插件和参数，第二次选择重复上下文 | 在所选配置内切换“编辑/使用” | 无“运行”一级入口；使用时不再选插件 |
| 可运行配置每次都先打开编辑器 | 日常动作是重复使用稳定配置，编辑不是主路径 | 同页保留“编辑/使用”，可运行配置默认进入“使用” | 点击有效配置后可直接填参数并加入队列 |
| 资源树所有配置使用同一文件图标 | 用户必须逐个打开才能判断能否运行或哪里需要修复 | 用不同形状和克制颜色区分类别，错误详情打开后显示 | 四类状态可扫描且不只依赖颜色 |
| 把错误全文或多个徽标塞进资源树 | 树从索引变成问题报告，文件名和层级被挤压 | 树只显示状态装饰，详细错误归打开后的工作区 | 树行保持单行，错误仍可定位 |
| 全局导航长期放置主题按钮 | 主题是低频偏好，不是跨页主任务 | 移入“设置”的外观区，保留本地记忆 | 全局导航只承担页面切换；设置页可切换并在刷新后恢复 |
| “离线时间校准” | 部署背景不是用户正在执行的动作，且“离线”没有改变操作 | 使用“时间校准”，加载服务器当前时间作为上下文和默认值 | 设置页打开后显示服务器时间且输入不为空 |

## 已确认的通用反例

- 产品名、装饰图标和副标题同时占据导航顶部，但不帮助选择页面。
- 角色徽标长期显示；权限已经由可用入口表达，只有认证失败需要提示。
- 自动同步同时保留“刷新”按钮，却没有独立恢复用途。
- 数量为零的任务状态仍渲染完整分区。
- 把 API 拥有的全部筛选器复制到网页，尽管网页用户没有提出筛选任务。
- 同一状态同时由徽标、段落、颜色、时间和页脚重复表达。
- 成功和失败写死在网页；插件已有更准确的“验证通过、需要关注、未通过”等领域状态。
- 操作成功通知长期覆盖后续按钮；短时反馈不得抢占点击区域。
- 把成功反馈插入所属页面的文档流，会挤动编辑器、工具栏和资源树；应进入避开主动作的固定通知层，并以布局矩形门验证零位移。阻塞错误才在所属内容中持续保留。详见 [把瞬时反馈放进工作区文档流](normal-flow-notification-shifts-workbench.md)。

## 新增元素登记规则

新增常驻元素前，必须在本目录补充其用户问题、删除后果、显示频率和唯一语义所有者。无法写出删除后果的元素默认不加入首屏。项目级决定保存在这里；跨项目规则聚合到用户根部 `modern-web-interface-design/subskills/concise-no-fluff-interface/references/redundancy-counterexamples.md`。
