# 反例：用户要求顺序扫描后仍保留多列 Case

## 症状

宽屏把 Case 自动排成多列卡片；视线需要在横向与纵向之间跳转。后续只调整卡片宽度、颜色或间距，没有改变被用户否定的布局所有权。

## 为什么失败

- “空间足够”不等于“应该多列”；Case 是按名字顺序扫描和调整次数的操作列表。
- 多列使框选、滚轮批量调整和键盘焦点的前后关系更难预测。
- 只检查行高和“不留空白”会放过错误列数，属于质量 Oracle 缺口。

## 拒绝门

- 所有 Case 行的横坐标必须一致，纵坐标必须逐项不同。
- 每行至少占列表内容宽度的 95%，保持单行紧凑。
- hover/focus 状态反馈不超过 100ms；焦点必须可见且不能改变次数。
- 点击、滚轮、框选、批量编辑、宽窄视口和资源预算必须一起回归。
