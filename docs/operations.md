# LocalFlow Ubuntu 运维

## 部署身份

推荐建立专用系统用户 `localflow`，主服务不使用 root。运行根目录归该用户所有，普通用户通过 HTTP 只读投影查看状态。系统时间调整安装单独的特权辅助程序，并用 polkit 或 sudoers 仅开放固定参数动作。

## 启动方式

主服务由固定 systemd 服务管理。启动参数只指定运行根目录；监听地址、端口和保存期来自配置文件。默认端口为 `0`，服务启动后可通过以下命令读取地址：

```bash
sudo -u localflow localflow status --root /var/lib/localflow
```

管理员登录使用：

```bash
sudo -u localflow localflow login-code --root /var/lib/localflow
```

程序客户端从管理员分配的只读密钥文件读取当前代次。不要把密钥复制到 shell 历史、命令参数或网页地址。

## systemd 服务建议

主服务单元应设置固定工作目录、自动重启、文件描述符上限和最小权限。任务由瞬态单元承载，单元名包含任务 ID，不包含用户提供的名称。瞬态单元属性限制在实现允许清单内，避免插件注入任意 systemd 属性。

升级主服务前先停止接收新任务并等待数据库短事务结束；不停止已有任务瞬态单元。新版本启动后执行恢复核对，再开放写接口。

## 中断与恢复

中断入口先向监督程序请求 `SIGINT`。监督程序不可达时，主服务通过 systemd 对控制组发送相同阶段信号。每次升级阶段都记录事件，最终状态以监督程序退出记录和 systemd 结果共同判定。

主服务异常重启后，不应手工删除 `runtime` 或 `logs`。恢复程序会检查未结束任务。只有确认任务进程不存在且没有退出记录时才标记 `lost`。

## 备份

一致性备份应暂停新写入，使用 SQLite 在线备份接口复制数据库，再复制配置、插件和仍需保留的日志。不要直接复制正在变化的 WAL 文件组合。密钥单独保护，恢复到新主机后建议立即轮换。

## 清理

清理程序只从存在结束时间的终态任务中选择数据。日志期限到达时删除对应任务日志目录但保留较新的历史记录；任务期限到达时在一个 SQLite 短事务中删除确认、批次关系、关联事件和任务，然后删除其日志目录。事件和幂等记录使用事件期限独立清理。运行中与排队任务不参与清理。

## 运行检查

- 服务健康接口、数据库写入和文件监视器正常。
- 任务执行器可创建瞬态单元，监督程序版本匹配。
- 密钥和端口文件所有者、类型及权限正确。
- 磁盘剩余空间高于配置阈值，日志目录可写。
- 当前墙钟、单调计时状态和最近时间校准记录可读取。
- 匿名请求对全部写接口返回拒绝，并且响应不包含受限字段。

## Ubuntu 验收

发布前必须在具有真实 systemd 的 Ubuntu 环境运行目标机测试：长任务跨主服务重启、三级中断、进程组子进程、端口随机与固定模式、文件权限、密钥轮换竞态、时间跳变和日志断线续传。容器中没有 systemd 的测试只能证明应用逻辑，不能替代这些结果。
