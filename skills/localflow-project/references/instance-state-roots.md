# 工作区复用与实例数据隔离

## 路径所有权

- 工作区：`config.yaml`、`config/`、`plugins/`、`scripts/`、`secrets/`。Case 候选由插件生成或从其显式配置的外部路径发现，核心不得创建通用 `cases/`。
- 实例数据：`runtime/`、`logs/`、`cache/`、`exports/`、实例锁和状态格式标记。
- 相对任务工作目录和插件 `context.root` 永远属于工作区；数据库、日志、端口、PID、监督描述与清理器永远属于实例数据。

## 入口和兼容

`localflow --workspace PATH --data PATH` 没有子命令。默认工作区是当前目录，默认实例数据是 `./.localflow`。旧 `--config-root`、`--state-dir` 只作为隐藏兼容别名；新旧拼写冲突时拒绝启动。旧单根历史只通过显式 `--data .` 继续使用，不自动移动，因为未结束的 systemd 监督进程可能仍引用旧路径。

损坏或过旧状态只允许隔离到数据目录的 `recovery/`；未来版本标记拒绝降级打开。任何恢复路径不得触碰工作区或密钥。

## 多实例门禁

1. 两个应用使用同一工作区、不同数据目录，分别提交任务并断言数据库、日志、端口和历史零交叉。
2. 数据目录不改变相对 `working_directory` 的解析结果。
3. 同一数据目录的第二个控制器在数据库打开前失败，释放后可重新取得。
4. systemd 单元名包含数据目录摘要；旧描述没有记录单元名时仍回退旧命名以便恢复。
5. 共享密钥只首次原子创建；并发首次启动不能互相覆盖或留下临时文件。
6. 冻结制品从工作区外启动，并显式传入两个目录；确认工作区没有 `runtime/`、`logs/`、缓存或核心创建的 `cases/` 副作用。

SQLite 数据目录只能由一个主机本地使用；文件锁不是 NFS 上的分布式数据库协议。共享配置的并发网页编辑仍使用版本检查与原子替换，但管理员必须协调同一文件的跨主机同时写入。
