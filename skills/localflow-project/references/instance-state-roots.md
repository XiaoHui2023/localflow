# 配置复用与实例状态隔离

## 路径所有权

- 配置根：`config.yaml`、`config/`、`plugins/`、`scripts/`、`cases/`、`secrets/`。
- 实例状态根：`runtime/`、`logs/`、`cache/`、`exports/`、实例锁和状态格式标记。
- 相对任务工作目录和插件 `context.root` 永远属于配置根；数据库、日志、端口、PID、监督描述与清理器永远属于状态根。

## 入口和兼容

`localflow --config-root PATH --state-dir PATH` 没有子命令。默认配置根是当前目录，默认状态根是 `./.localflow`。旧单根历史只通过显式 `--state-dir .` 继续使用，不自动移动，因为未结束的 systemd 监督进程可能仍引用旧路径。

损坏或过旧状态只允许隔离到状态根的 `recovery/`；未来版本标记拒绝降级打开。任何恢复路径不得触碰配置或密钥。

## 多实例门禁

1. 两个应用使用同一配置根、不同状态根，分别提交任务并断言数据库、日志、端口和历史零交叉。
2. 状态根不改变相对 `working_directory` 的解析结果。
3. 同一状态根的第二个控制器在数据库打开前失败，释放后可重新取得。
4. systemd 单元名包含状态根摘要；旧描述没有记录单元名时仍回退旧命名以便恢复。
5. 共享密钥只首次原子创建；并发首次启动不能互相覆盖或留下临时文件。
6. 冻结制品从配置目录外启动，并显式传入两个根；确认配置根没有 `runtime/`、`logs/` 或缓存副作用。

SQLite 状态根只能由一个主机本地使用；文件锁不是 NFS 上的分布式数据库协议。共享配置的并发网页编辑仍使用版本检查与原子替换，但管理员必须协调同一文件的跨主机同时写入。
